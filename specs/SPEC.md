# «Последний Архивариус» — спецификация Спринта 1

Статус: черновик v0.3 (2026-10-02) — читаемость поля боя (6.5), производительность отрисовки (6.6)
Движок: Godot 4.7.2 (`C:\Godot`), GDScript
Цель спринта: «скучный, но полный» прототип. Проверяем, интересен ли бой, хочется ли менять состав армии и работает ли распад воспоминаний.

---

## 1. Принятые решения

| Область | Решение |
|---|---|
| Язык | GDScript, статическая типизация везде, где возможно |
| Графика | 2D, плейсхолдеры: цветные гексы, простые фигуры/иконки, текст |
| Платформа | ПК, мышь, базовое разрешение 1920×1080, stretch `canvas_items`, aspect `expand` |
| Локализация | Русский; все строки — через ключи `TranslationServer` (`translations/strings.csv`), EN позже |
| Поле | 11×9 гексов, pointy-top, offset-координаты odd-r |
| Отряд | Стек: `count` существ × `hp` каждого |
| Случайность | Диапазон урона min–max, без промахов/удачи/морали; seeded RNG |
| Очередь ходов | Раунды по инициативе, действия «Ждать» и «Защита» (модель HoMM3) |
| Способность | Дальняя атака (стрелки) |
| Распад | Прочность на карте; потери в бою не перманентны |
| Колода → бой | Перед боем игрок выбирает до 5 карт отрядов из Кодекса |
| Забег | Цепочка из 3 боёв с ростом сложности |
| Данные | Custom Resource (`.tres`) |
| Тесты | GUT (аддон в `addons/gut`) |
| VCS | git + `.gitignore` для Godot |

## 2. Игровой цикл спринта

```
Главное меню
 ├─ Новый забег → генерируется seed, стартовый Кодекс
 └─ Продолжить → загрузка user://run_save.json (если есть)
        ↓
Экран подготовки: выбор до 5 карт отрядов из Кодекса  ◄──────┐
        ↓                                                      │
Бой N (N = 1..3)                                               │
        ↓                                                      │
 Победа → распад (−1 прочности участникам) → награда 1 из 3 ──┘ (если N < 3)
 Победа в бою 3 → экран «Экспедиция завершена»
 Поражение → экран «Архивариус пал», сохранение удаляется
```

Условия поражения забега:
- поражение в бою;
- перед боем в Кодексе не осталось ни одной карты отряда.

## 3. Тактический бой

### 3.1 Поле
- 11 колонок × 9 строк, pointy-top, odd-r offset (`Vector2i(col, row)`).
- Внутри — перевод в cube/axial для расстояний и соседей.
- Стартовые зоны: игрок — колонка 0, AI — колонка 10. Отряды расставляются автоматически по строкам 0, 2, 4, 6, 8 в порядке выбора.
- Препятствия: 2–4 непроходимых гекса, задаются шаблоном арены (`BattleTemplate`), колонки 2–8.

### 3.2 Очередь ходов
- В начале раунда все живые стеки сортируются по инициативе (убыв.). При равенстве — сторона игрока первой, затем по `id`.
- **Ждать**: стек перемещается в конец раунда (фаза ожидания); ожидающие ходят в порядке *возрастания* инициативы. Ждать можно один раз за раунд.
- **Защита**: ход завершается, `+30%` к защите до начала следующего хода стека.
- Конец раунда: сбрасываются `retaliated`, `waited`, `moved`.
- Лимит: 30 раундов → поражение игрока (защита от патов).

### 3.3 Действия активного стека
1. Перемещение на достижимый гекс (BFS по сетке, лимит = `speed`, препятствия и стеки блокируют).
2. Ближняя атака: перемещение на соседний с целью гекс + удар. Игрок выбирает, с какой стороны атаковать (по позиции курсора на гексе цели).
3. Выстрел (только `is_ranged`, есть `shots > 0`, **нет врага вплотную**): атака любой видимой цели без ответа. Видимость в спринте не проверяется.
4. Ждать / Защита.

Стрелок с врагом вплотную может атаковать только в ближнем бою с уроном ×0.5.

### 3.4 Формула урона
```
base      = Σ по count: randi_range(dmg_min, dmg_max)   # при count > 10 — count × rand один раз
diff      = attack − defense_effective
mod       = diff > 0 ? 1 + 0.05 × min(diff, 60)        # максимум ×4
                     : 1 − 0.025 × min(−diff, 28)       # минимум ×0.3
range_mod = 0.5, если выстрел на расстояние > 5 гексов, иначе 1.0
melee_shooter_mod = 0.5 для стрелка в ближнем бою
damage    = max(1, floor(base × mod × range_mod × melee_shooter_mod))
```
Урон снимается сначала с `current_stack_hp` верхнего существа, затем убивает целых существ. Стек с `count == 0` удаляется с поля.

### 3.5 Ответный удар
- Один раз за раунд, только на ближнюю атаку, только если стек выжил.
- Считается по той же формуле от оставшегося `count`.
- Стрелок отвечает с модификатором ×0.5.

### 3.6 Победа и поражение в бою
- Победа: у AI не осталось стеков.
- Поражение: у игрока не осталось стеков или превышен лимит раундов.
- Дополнительные цели (алтарь и т. п.) — не в этом спринте, но `BattleState` содержит поле `objective` с единственным значением `ELIMINATE`.

### 4.3 Распад
- После **победы** каждая карта, выставленная в бой, теряет 1 прочность (даже если стек погиб).
- На 0 прочности карта удаляется из Кодекса с экраном «Воспоминание угасло».
- Потери `count` в бою не переносятся.

### 4.4 Награда
- После победы в боях 1 и 2: 3 случайные карты из пула (seeded), игрок берёт одну или пропускает.
- Пул наград = все карты из 4.2. Дубликаты в Кодексе допустимы.
- Ограничение Кодекса в спринте: 12 карт; при переполнении нужно выбросить одну.

## 5. AI (простой, без поиска по дереву)

Для активного стека AI:
1. **Стрелок, не заблокирован** → выстрел по цели с максимальной оценкой `урон_ожидаемый / угроза_цели`, приоритет стрелкам игрока.
2. **Может дойти и ударить** → перебирает все пары (гекс атаки, цель), выбирает максимум `ожидаемый_урон − 0.5 × ожидаемый_ответ`.
3. **Иначе** → движется к ближайшему врагу по кратчайшему пути на полную скорость.
4. Стрелок, заблокированный вплотную, бьёт в ближнем бою.

AI работает только с `BattleState` и `BattleResolver`, без узлов сцены. Ожидаемый урон = среднее `(dmg_min + dmg_max) / 2`.

### 6.2 Принципы
- **Defs** (`Resource`) — неизменяемые описания. **States** (`RefCounted`) — изменяемое состояние, ссылаются на def по `StringName id` через реестр.
- Все изменения боя — только через `BattleResolver.apply(state, action) -> Array[BattleEvent]`. Действие сначала проверяется `validate(state, action) -> bool`.
- `BattleEvent` (moved, attacked, damaged, died, retaliated, round_started, turn_started, battle_ended) — то, что проигрывает `BattleView` для анимаций. View никогда не меняет state.
- Один `RandomNumberGenerator` на бой, seed = `hash(run_seed, battle_index)`. Состояние RNG — часть `BattleState`.
- Каждый State имеет `to_dict()` / `static from_dict()`.

### 6.3 Сохранение
- Файл `user://run_save.json`, поле `version: 1`.
- Сохраняется на чекпоинтах: перед экраном подготовки и после выбора награды. Посреди боя не сохраняется — выход из боя = возврат к подготовке с тем же seed.
- Содержимое: `run_seed`, `battle_index`, Кодекс (id карт + прочность), RNG-состояние лута.

### 6.4 UI боя
- Подсветка: достижимые гексы, атакуемые цели, гекс под курсором, путь.
- Курсор над врагом: меч (ближний) с направлением атаки / стрела (выстрел) + превью «урон X–Y, убьёт A–B».
- Панель очереди ходов (текущий раунд + следующий).
- Кнопки и хоткеи: Ждать (`W`), Защита (`D`).
- Лог боя (последние 8 событий).
- Ход AI проигрывается с задержкой ~0.4 с на событие.

### 6.5 Читаемость поля боя
Цель: игрок понимает, кто ходит и что умеет каждый отряд, не открывая описаний. Арт по-прежнему плейсхолдер — всё рисуется кодом (`UnitGlyphs`), замена на спрайты не меняет остальной UI.

**Силуэты существ** (по `def_id`, внутри круглой фишки цвета существа):

| Существо | Силуэт |
|---|---|
| Соляной Страж | щит с крестом |
| Летописец-стрелок | свиток с пером |
| Пепельный Гуль | следы когтей |
| Осколочный Лучник | лук со стрелой |
| Эхо Грозового Змея | молния |
| Ржавый Часовой | башня |

Неизвестный `def_id` рисуется кругом — новое существо видно сразу, даже без силуэта.

**Фишка на поле:**
- обод — цвет стороны (синий — игрок, красный — противник);
- снизу — численность и полоска ОЗ верхнего существа (зелёная → красная);
- значки вокруг фишки: стрелок + оставшиеся выстрелы (сверху слева; серый, если выстрелов нет), летает (сверху справа), в защите (слева), ответный удар потрачен (справа).

**Ходящий стек:** пульсирующее золотое кольцо, золотая заливка его клетки и подпрыгивающая стрелка над фишкой; в очереди — увеличенный портрет с золотой рамкой. Строка статуса: «Ваш ход: X» (синим) / «Ход противника: X» (красным).

**Очередь ходов:** портреты с силуэтом и численностью вместо текстовых аббревиатур; следующий раунд — полупрозрачно.

**Карточки справа** (`UnitInfoPanel`):
- «Ходит сейчас» — всегда активный стек;
- «Под курсором» — любой другой стек под мышью (скрыта, если пусто).

Карточка: портрет, «Название × N», ОЗ верхнего существа, Атк/Защ/Урон и Скор/Иниц, затем список способностей и состояний со значками и описанием простым языком. Список (`UnitInfoPanel.abilities_of`):

| Значок | Когда | Текст |
|---|---|---|
| меч | не стрелок | ближний бой, получает ответный удар |
| стрела | стрелок | выстрелы, без ответа, ½ урона дальше 5 клеток, блокировка вплотную |
| крыло | летает | перелетает препятствия и отряды |
| скрещённые мечи | ответ не потрачен | ответит первому ударившему вплотную |
| скрещённые мечи, перечёркнуты (серым) | ответ потрачен | — |
| щит | защищается | +30% защиты до своего хода |
| песочные часы | ждёт | походит в конце раунда |

**Зона угрозы:** при наведении на вражеский стек ближнего боя красным контуром обводятся клетки, куда он может дойти в свой ход. Для стрелков не показывается (они бьют по всему полю — это сказано в карточке).

**Иконка у курсора:** стрелка (перемещение), меч (ближняя атака) или стрела (выстрел) — то же действие, что выполнит клик.

### 6.6 Производительность отрисовки
Цель: стабильные 60 FPS на поле боя. Перестроение canvas-команд в Godot (триангуляция полигонов, сглаженные линии) дорогое, а показ уже записанных команд почти бесплатен. Поэтому `BattleView` разбит на слои, и каждый перерисовывается только при своих изменениях:

| Слой | Что рисует | Когда перерисовывается |
|---|---|---|
| board | сетка, препятствия | один раз при создании боя |
| overlay | достижимость, путь, угроза, наведение, цель | при смене клетки/действия под курсором и после хода |
| marker | кольцо и стрелка ходящего стека | никогда: пульсация через `modulate`/`scale`/`position` |
| units | фишки | при синхронизации и в кадрах анимации |
| fx | снаряд, всплывающий урон | только пока они есть |
| cursor | иконка действия | при смене вида; движение через `position` |

Правила:
- никакого `queue_redraw()` каждый кадр «на всякий случай»;
- наведение мыши пересобирает подсветку и карточки, только если изменились клетка, действие или возможность ходить (кэш-ключ в `battle_screen.gd`);
- контуры сетки и зоны угрозы — одним `draw_multiline`, без сглаживания;
- заливки гексов и плоские фигуры слоя — одним массивом треугольников (`BattleView.FillBatch`), а не `draw_colored_polygon` на каждый гекс: каждый вызов — отдельный draw call;
- силуэты и значки рисуются без antialiasing.

Замер: `tools/profile_battle.tscn` (в окне, не headless). Ориентиры на 2026-10-02: покой — ~60 FPS (кадр ~16,5 мс, упор во vsync); движение мыши со сменой клетки каждый кадр — 57–60 FPS; анимации хода противника — средний кадр 16 мс, худший ~35 мс. До разбиения на слои было 2 FPS. Карточка «Под курсором» пересобирается, только если изменился стек или его состояние.

### 6.7 Звук
Плейсхолдер, синтезированный кодом: `tools/gen_audio.gd` генерирует WAV в `res://audio` (22 050 Гц, моно; при импорте — сжатие QOA). Внешних файлов и лицензий нет; любой звук заменяется файлом с тем же путём.

- **Музыка** — два лупа с плавной сменой (1,2 с): `menu` (эмбиент, ре минор, 32 с) на всех экранах вне боя, `battle` (ля минор, 100 уд/мин, 38 с) в бою. Петля задана в настройках импорта (`edit/loop_mode=2`).
- **Эффекты** — автозагрузка `Audio`: пул из 10 голосов, разброс высоты ±5%, один и тот же звук не чаще раза в 40 мс. Таблица id → [файл, дБ] — `Audio.SFX`.
- **Озвучка событий боя** — `BattleView.sound_for`: перемещение, удар/выстрел (+ попадание снаряда), смерть, лечение, урон заклинанием, отталкивание, стена, способность, приказ/заклинание. Экран боя: начало хода игрока, победа/поражение. Интерфейс: клик кнопки, выбор карты, превращение карты.
- **Громкость** — шины `Music` и `SFX`, ползунки в главном меню, хранится в `user://settings.cfg`.

Перегенерировать звук:
```
godot --headless -s res://tools/gen_audio.gd
godot --headless --import
```

Обязательное покрытие:
- `hex_grid`: соседи на чётных/нечётных строках, расстояние, границы поля.
- `pathfinding`: достижимость с препятствиями и стеками, полёт.
- `damage_calc`: модификаторы атаки/защиты, крайние значения, дальний штраф, стрелок вплотную.
- `turn_order`: инициатива, тай-брейк, Ждать (обратный порядок), новый раунд.
- `resolver`: перемещение, атака, ответ один раз за раунд, смерть стека, блок выстрела вплотную, конец боя.
- `ai`: выбирает выстрел, когда может; выбирает убийственную атаку; идёт к врагу.
- `codex`: распад, удаление на 0, лимит 12.
- `save`: round-trip `RunState` → JSON → `RunState`.
- Детерминизм: один seed + одни действия → идентичный итоговый `BattleState`.
- `scenes`: экраны создаются без ошибок, AI доигрывает до хода игрока, курсор выбирает верное действие и сторону удара, список способностей отражает состояние стека.
- `audio`: все файлы банка загружаются, музыка зациклена, каждое событие боя озвучено звуком из банка, громкость сохраняется.
- `translations`: каждая строка CSV — ровно 2 столбца (запятые в тексте — только в кавычках), нет дубликатов, все ключи из `tr("...")` в UI и `name_key` в данных существуют.
